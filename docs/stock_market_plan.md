# 주식 시장 설계 (확정·구현)

마피아 봇에 들어간 주식 시장의 설계입니다. 처음 초안을 운영자가 확인한 결정(맨 아래 "확정한 결정")에 맞춰 고쳤고, 지금 코드와 같습니다. 엔진은 `src/stocks/`, 봇 연결은 `src/stock_hub.rs`, Discord 명령은 `src/commands/stock_cmds.rs`, 증권 사이트 서버는 `src/stock_web.rs`, 사이트 화면은 `stocks-web/`에 있습니다.

---

## 목표와 원칙

- **현실감**: 한국 증시의 규칙과 가격 움직임을 따릅니다. 호가 단위, 가격제한폭 ±30%, 시장가·지정가, 수수료·거래세, 실적 발표, 배당, 뉴스·루머·공시, 지수, 변동성 완화장치, 서킷브레이커, 공모주 청약, 유상증자, 자사주, 관리종목·상장폐지를 넣었습니다.
- **공정성**: 무위험 차익이나 시세 조종으로 버는 길이 없어야 합니다. 가격 영향 모형과 수수료로 이를 보장하고, 테스트로 확인합니다.
- **코인 순환과의 연결**: 수수료·거래세·설립 수수료·공모 수수료는 복지 금고로 갑니다. 시장 전체가 코인을 얼마나 만들고 없애는지는 운영 설정(드리프트)으로 조절하고, 관리자가 `/주식관리`에서 집계를 봅니다.
- **적은 인원에서도 살아 있는 시장**: 가격은 시뮬레이션이 움직이고, 시장조성자(LP)가 늘 호가를 냅니다. 플레이어의 주문은 가격을 실제로 움직입니다.
- **플레이어가 만드는 회사**: 누구나 코인으로 회사를 세우고, 공모로 상장하고, 배당·증자·자사주로 경영할 수 있습니다. 실적이 나쁘면 관리종목을 거쳐 상장폐지되고, 자본이 바닥나면 파산합니다.

## 핵심 결정

| 결정 | 채택 | 이유 |
|---|---|---|
| 가격 출처 | **가상 종목 시뮬레이션** | 실제 시세 연동은 외부 API·약관 문제가 있고, 평일 낮에만 움직이며, 게임 안 뉴스·이벤트를 만들 수 없음 |
| 거래 상대 | **시장조성자(LP) 호가 + 플레이어 지정가** | 인원이 적어 플레이어끼리만으로는 호가가 빔 |
| 결제 | **즉시 결제(T+0)** | 실제 T+2는 게임에서 번거롭기만 함 |
| 공매도·신용 | **없음** | 잔액이 음수가 되는 경우와 강제 청산을 다뤄야 하고, 잃는 속도가 너무 빠름 |
| 장 운영 | **24시간** | 서버 사람들이 아무 때나 거래 |
| 게임 달력 | **게임 하루 = 실제 1시간, 분기 = 실제 1주** | 가격제한폭·VI·배당 지급·청약 기간이 한 시간 단위로 돌고, 실적은 매주 |
| 플레이어 회사 | **설립·상장·경영·파산·상장폐지 모두** | 운영자 요청 |
| 웹 HTS | **Discord와 함께, 카지노와 따로 떨어진 밝은 화면의 사이트(마피아증권)** | 운영자 요청 |

- **지수**: "마피아 종합지수"(상장 종목 시가총액 가중, 첫날 1,000). 상장·상장폐지·증자 때는 지수가 튀지 않게 제수를 고칩니다.
- **새 시스템 상장**: 시스템 회사가 상장폐지되어 목표 수(기본 12)보다 적어지면, 다음 게임일에 새 가상 회사가 공모 청약을 거쳐 상장합니다 (코드 200010부터).
- **게임 연동**: 실적 발표 때 지난 분기의 실제 활동(마피아 판 수 / 카지노 핸드 수와 하우스 손익)이 기준보다 많으면 실적이 좋아집니다. 반영 폭에는 상한이 있어, 일부러 카지노에서 잃어 주가를 올리는 것은 손해입니다.

### 거래 규칙

- **24시간 거래**. 게임 하루(기본 실제 1시간)가 바뀔 때 전일 종가가 새로 잡히고, 가격제한폭과 VI 기준도 그 값을 따릅니다.
- **호가 단위** (한국거래소와 같게): 2,000 미만 1, 5,000 미만 5, 2만 미만 10, 5만 미만 50, 20만 미만 100, 50만 미만 500, 그 이상 1,000.
- **가격제한폭**: 전일 종가 대비 ±30%. 상장 첫날은 공모가의 60~400%.
- **변동성 완화장치(VI)**: 기준가에서 ±10% 움직이면 그 종목 거래를 2분 멈춥니다.
- **서킷브레이커**: 지수가 전일보다 8% 떨어지면 게임일에 한 번, 모든 거래를 5분 멈춥니다.
- **게임일 넘기기** (`/주식관리 게임일 넘기기 [일수]`, 1~24일): 시장에는 자기 시계가 있고, 관리자가 넘기면 시장 시계가 그 게임일의 시작으로 건너뜁니다. 그 사이의 시세는 5초 단위로 바로 따라잡고, 청약 마감·배당 지급·유상증자·자사주·정리매매·보호예수·주문 만료처럼 시각으로 정한 일정도 그만큼 앞당겨집니다. 시장의 모든 시각(뉴스·봉·주문)은 이 시계를 쓰며, 시세판과 증권 사이트에 앞선 만큼을 표시합니다.

## 가격 엔진

5초마다 모든 종목을 갱신합니다. 봇이 꺼져 있던 동안은 켜질 때 5초 단위로 따라잡습니다 (최대 1주).

1. **팩터 모형**: 한 틱의 로그 수익률 = 시장 팩터 × 베타 + 업종 팩터 + 투자 심리 + 종목 잡음 + 주문 영향. 시장 팩터 때문에 종목들이 함께 움직이고, 업종이 같으면 더 비슷하게 움직입니다.
2. **두꺼운 꼬리**: 충격은 t-분포(자유도 4)에서 뽑습니다.
3. **변동성 군집**: GARCH 방식으로, 크게 움직인 뒤에는 한동안 변동성이 커집니다.
4. **하루 안의 패턴**: 게임일 시작 직후와 마감 직전에 변동성이 큽니다 (U자형).
5. **투자 심리**: 뉴스·실적·수급이 바꾸고 몇 주에 걸쳐 돌아갑니다. 뉴스 충격은 몇 분에 걸쳐 가격에 옮겨 가므로 뉴스를 먼저 읽고 판단한 사람이 유리합니다.
6. **시장 국면**: 안정기와 하락·고변동 국면이 바뀝니다.
7. **드리프트**: 시장 전체의 기대 수익률(기본 실제 1주 +0.1%)이 주식 시장이 장기적으로 만드는 코인을 정합니다.
8. **거래량**: 틱마다 가상의 거래량(평균 거래량 × 하루 안의 패턴 × 움직임 크기)을 더하고, 플레이어 주문의 체결량을 더합니다. 1주에 못 미치는 몫은 다음 틱으로 넘깁니다. 플레이어 회사는 주식이 적어(수백~수천 주) 발행 주식의 약 30%가 하루에 오가는 것으로 봅니다. 가상 거래량은 화면(거래량·거래대금·차트)에만 쓰고 주주·코인은 바꾸지 않습니다.

## 뉴스·공시·실적·배당

- **뉴스**: 종목 뉴스(종목당 실제 하루 약 0.8건)와 경제 뉴스(하루 약 3건). 강도에 따라 투자 심리를 바꿉니다.
- **루머**: 확인되지 않은 소문이 돌고, 나중에 공시로 사실 여부가 밝혀집니다. 거짓이면 올랐던 만큼 되돌아갑니다.
- **실적**: 종목마다 실제 1주마다 발표합니다. 발표 하루 전에 예상치(컨센서스)를 공개하고, 실제 실적과 예상치의 차이(서프라이즈)만큼 주가가 반응합니다.
- **시스템 회사 배당**: 배당주는 분기 이익에서 주당 배당을 정해 보유자에게 코인으로 줍니다.

## 주문과 체결

- **시장가**: 호가를 차례로 먹으며 체결하고, 남은 수량은 취소합니다.
- **지정가**: 현재가 ±10% 안에서 받습니다. 바로 체결되지 않은 수량은 호가에 남고(최대 24게임일), 조건이 맞으면 체결됩니다.
- **증거금 100%**: 매수 주문은 필요한 코인을 먼저 묶고 쓰지 않은 만큼 돌려줍니다. 매도 주문은 그 주식을 묶습니다. 마피아 판에 걸린 배팅액은 쓸 수 없습니다.
- **시장조성자(LP) 호가**: 호가 중심(모형 가격)의 위아래로 10단계씩 냅니다. 단계마다 물량이 정해져 있어 큰 주문은 여러 호가를 먹습니다 (슬리피지).
- **가격 영향**: 영구 영향은 LP와 체결된 수량에 선형입니다 (Huberman–Stanzl: 사고팔기를 반복해 가격을 조종해도 이익이 나지 않음). 체결 뒤 호가 중심은 절반만 따라가므로 즉시 되팔면 반드시 손해입니다.
- **플레이어끼리 체결**: 호가 중심 ±2% 안에서만 체결됩니다 (엉뚱한 가격으로 코인을 넘기는 우회 선물 방지). 같은 사람의 주문끼리는 체결되지 않습니다.
- **한도**: 시스템 회사는 1인 보유가 발행 주식의 5%까지, 주문 1회 수량은 게임 하루 평균 거래량의 20%까지. 플레이어 회사는 주문 1회 발행 주식의 20%까지.

## 플레이어 회사

| 단계 | 규칙 (기본값) |
|---|---|
| **설립** (`/회사 설립`) | 자본금 1,000,000 이상 + 설립 수수료 1%(금고). 액면 5,000으로 주식을 발행해 모두 설립자가 갖습니다. 한 사람 1개 |
| **상장** (`/회사 상장`) | 설립 1게임일 뒤, 자본총계 1,000,000 이상. 공모가는 주당 순자산의 0.8~3배, 신주는 기존 주식의 10~100% (대표 지분 50% 이상 유지). 청약 1게임일 |
| **청약·배정** (`/주식 청약`) | 증거금 = 공모가 × 수량. 청약이 공모 주식의 50%에 못 미치면 무산(전액 반환). 넘치면 절반은 균등, 나머지는 비례로 배정하고 남은 증거금은 반환. 공모 대금에서 공모 수수료 1%(금고)를 뗀 만큼이 회사 현금이 됨 |
| **상장 후** | 설립자 지분은 24게임일 보호예수. 첫날 가격 범위는 공모가의 60~400% |
| **분기 실적** | 회사 현금(자본총계) × (기대 수익률 + 위험도에 따른 변동)이 이익·손실. **실제 코인이 회사에 생기거나 사라집니다** |
| **위험도** (`/회사 위험도`) | 1~5단계, 실제 1주에 한 번 변경. 높을수록 실적 변동(분기 2~30%)과 주가 변동이 큼 |
| **배당** (`/회사 배당`) | 회사 현금에서 주당 배당. 다음 게임일 시작에 주주에게 지급 |
| **유상증자** (`/회사 유상증자`, `/회사 신주인수`) | 주주에게 보유 비율대로 신주인수권 배정, 발행가는 현재가의 70~100%, 1게임일 동안 행사. 대금은 회사 현금 |
| **자사주** (`/회사 자사주`) | 회사 현금의 절반까지 예산, 1게임일 동안 시장에서 사서 소각. 그동안 대표는 매도 불가 |
| **관리종목** | 자본총계가 납입 자본의 절반 아래로 내려가면 지정. 다음 분기에도 그대로면 상장폐지 결정 → 정리매매 6게임일 |
| **파산** | 자본총계가 0 이하 → 비상장은 바로 해산, 상장사는 정리매매 6게임일 뒤 상장폐지 (주주는 0) |
| **해산** (`/회사 해산`) | 비상장은 바로 해산하고 남은 현금을 돌려받음. 상장사는 대표 지분 50% 이상일 때 1게임일 거래정지 뒤 남은 현금을 주주에게 나누고 상장폐지. 회사 이름을 그대로 입력해야 함 |

- 상장폐지 때 걸려 있던 주문·청약 증거금·행사한 신주 대금은 돌려줍니다.
- 비상장 주식은 주당 순자산으로, 상장폐지된 주식은 0으로 평가합니다.

## 비용과 코인 순환

| 항목 | 기본값 | 가는 곳 |
|---|---|---|
| 매매 수수료 (매수·매도) | 0.015% (최소 1) | 복지 금고 |
| 증권거래세 (매도) | 0.2% | 복지 금고 |
| 회사 설립 수수료 | 자본금의 1% | 복지 금고 |
| 공모 수수료 | 공모 대금의 1% | 복지 금고 |
| 스프레드 | 종목별 | LP (사라짐) |

- LP에게서 사면 코인이 사라지고, LP에게 팔면 새로 생깁니다 (카지노 칩과 같음). 시스템 회사 배당은 코인을 만들고, 시스템 회사 공모 대금은 사라집니다. 플레이어 회사의 분기 이익·손실은 회사 현금을 늘리거나 줄입니다. 모두 `/주식관리`에서 누적을 봅니다.
- **환급 제외**: 주식 매매는 일간 롤링·주간 손실 환급에 들어가지 않습니다 (변동이 큰 종목으로 이기면 갖고 지면 환급받는 공짜 옵션, 거래량 부풀리기 방지). 대신 수수료·세금이 금고로 들어가 모두의 환급 재원이 됩니다.
- **구조금 기준에 주식 포함**: 보유 코인 + 테이블 칩 + 주식 평가액 + 묶인 증거금이 기준 미만일 때만 받습니다.

### 증권 사이트 (마피아증권)

카지노와 따로 떨어진 밝은 화면의 웹사이트입니다. `/주식 증권`이 주는 개인 링크(`/stocks/<토큰>`, 12시간 유효)로 엽니다. 프론트엔드는 `stocks-web/`(Vite + React)이고, Activity 서버가 카지노 웹과 같은 포트에서 서비스합니다. 개인 링크 세션만 카지노와 같은 표를 씁니다 (토큰은 누구인지 확인할 뿐).

- 종목 목록·검색, 캔들 차트(분봉·일봉, 이동평균, 거래량, 십자선), 종합지수 차트
- 호가창 10단계(휴대폰 5단계, 누르면 그 가격이 지정가로), 내 주문·플레이어 주문 표시
- 주문 창: 매수·매도, 지정가·시장가, 호가 단위 ± 버튼, 10·25·50%·최대 수량, 수수료·세금 포함 예상 금액
- 종목 정보(개요·진행 중인 공모·증자·자사주·배당·청산), 분기 실적, 주주, 종목 뉴스
- 계좌: 총자산·손익 요약, 잔고, 미체결(취소), 체결, 공모·증자(내 청약과 청약 취소, 진행 중인 공모 청약, 진행 중인 유상증자와 신주인수), 내 회사(설립·상장·배당·증자·자사주·위험도·소개·해산), 순위(주식 재산 상위 50명과 내 순위, 30초마다), 시장 뉴스
- 관리 탭 (관리자만): 시장 집계, 종목 거래정지·재개, 게임일 넘기기, 시세판·뉴스 채널 연결(채널 ID, 시세판은 1분 안에 새 채널에 올리고 옛 것은 지움). `/주식 증권`을 쓴 사람이 관리자면 그 사람에게 12시간 관리 권한이 붙고, 서버가 요청마다 다시 확인합니다. 웹에서 한 관리 작업도 로그 채널에 남습니다
- 상태는 2초마다(탭이 가려지면 15초), 봉은 15초(일봉 1분)마다 새로 받습니다

API (개인 링크 토큰을 Bearer로): `GET /stocks/api/state?code=`, `GET /stocks/api/candles?code=&range=minute|day` (`code=INDEX`는 지수, 100배 정수), `GET /stocks/api/ranking`, `POST /stocks/api/order|cancel|subscribe|unsubscribe|company`, `POST /stocks/api/admin` (관리자만, `action`: `halt`·`resume`·`skip`·`channels`).

## 저장과 구조

- **엔진** (`src/stocks/`, 라이브러리): Discord·HTTP·코인 잔액을 모르는 순수 규칙. 시각과 난수를 호출자가 주므로 테스트에서 시드를 고정합니다.
- **코인 장부**: 코인이 오가는 일은 모두 엔진의 장부(`Transfer`)에 남기고, 허브가 통계 파일의 코인에 반영합니다. 반영한 마지막 번호를 통계 파일(`stock_ledger`)에 함께 저장해 같은 이동을 두 번 반영하지 않습니다.
- **저장 순서**: 시장 파일(`stocks.json`)을 먼저, 통계 파일을 나중에 쓰고, 둘 다 쓴 뒤에만 반영한 장부를 비웁니다. 그 사이에 멈추면 다음 시작 때 남은 장부를 한 번 반영합니다. 봉은 `stocks-candles.json`에 따로 저장합니다 (분봉 360개, 일봉 720개).
- **틱**: 5초마다 가격·주문·일정을 돌리고, 뉴스를 뉴스 채널에 올리고, 1분마다 시세판을 고칩니다.

## 검증 (테스트)

- 호가 단위 올림·내림, 가격제한폭, VI·서킷브레이커
- 매수 직후 매도하면 반드시 손해 (왕복 비용 > 0), 두 계정이 짜도 손익 합 0 이하
- 지정가·보유 한도·자전거래·플레이어 체결 가격 범위 거부
- 수수료·세금·설립·공모 수수료가 금고로 감, 증거금 예약과 반환
- 공모 배정(균등+비례), 무산 시 전액 반환, 보호예수
- 배당·유상증자·자사주·관리종목·파산·해산·상장폐지 때의 코인 흐름
- 같은 시드면 같은 시세, 긴 시뮬레이션에서 지수 수익률·변동성이 설정 근처
- 허브: 장부를 한 번만 반영, 재시작 후 남은 장부 반영, 배팅 잠금
- 웹 API: 세션 인증, 주문이 코인을 옮김, 잘못된 요청은 400과 안내
