# 딜러 클립·초상 규격 (하위 에이전트 작업용)

2026-09-23: 소피아의 대기·딜링·플립 영상(WebM·MP4)과 영상 포스터 `sophia-video.jpg`가 들어 있다. 이 PC에서 로컬 Wan 모델로 만들었고, 만드는 방법과 검수 결과는 `GENERATION.md`에 있다. 연출을 끄면 실사 사진 `sophia-table.png`가 보인다.

`DealerBackdrop.tsx`는 클립을 미리 로드하고 준비된 영상으로 전환한다. WebM을 먼저 시도하고 MP4로 대체한다. 무드 변경 시 DOM을 새로 만들지 않으며, 숨긴 영상·백그라운드 탭에서는 재생을 멈춘다. 화면 제목 옆의 연출 버튼이 딜러 영상과 카드·칩 애니메이션을 함께 끄고 켠다(기본 켜짐, 브라우저에 저장). 기기의 '동작 줄이기' 설정은 기본값에 쓰지 않는다. 실제 영상이 없으면 사진을 유지한다.

빌드 시 존재하는 `*-idle/deal/flip.webm/mp4` 파일 목록만 등록하므로 없는 영상은 요청하지 않는다. 영상을 추가하거나 교체한 뒤에는 웹을 다시 빌드한다. 개발 서버를 사용하는 경우 서버도 다시 시작한다.

웹은 `casino-web/public/dealers/` 아래 파일을 **있으면 자동으로** 쓴다. 파일이 없으면 다음 순서로 대체한다:
상황 클립 → `<id>-idle.webm` → `<id>.png` → `dealer.png`(소피아 사진).

## 파일 이름
| 파일 | 용도 | 재생 |
|---|---|---|
| `<id>.png` | 초상 (사진) | 영상이 없을 때, 그리고 사이드 패널 아바타(얼굴 부분을 CSS로 확대) |
| `<id>-video.jpg` | 영상 첫 프레임 | 연출이 켜져 있을 때 영상이 뜨기 전 포스터 (소피아만 코드에 연결) |
| `<id>-idle.webm` | 대기 루프: 숨 쉬고 살짝 움직이며 카메라를 본다 | 무음, 루프, 4~10초 (끝과 처음이 이어지게) |
| `<id>-deal.webm` | 카드 나누는 동작 (슈에서 카드를 꺼내 앞으로 밀어 준다) | 새 딜링 요청마다 1회. 공개 이벤트가 짧아도 동작 끝까지 재생 |
| `<id>-flip.webm` | 카드 뒤집는 동작 (쇼다운, 딜러 홀 카드 오픈) | 새 플립 요청마다 1회. 종료 후 준비된 대기 영상으로 전환 |

`<id>`는 `src/casino/table.rs`의 `DEALERS` 목록: `sophia`, `mia`, `hana`, `lina`.
파일을 넣은 뒤 그 딜러의 `has_portrait`를 `true`로 바꾸면 12판마다 교대에 들어간다.

## 구도
- 원본 `casino-web/public/dealer.png`(1536×1024)와 **같은 카메라·같은 테이블·같은 조명**. 딜러가 화면 가로 중앙, 머리가 위쪽 30% 안에 오게 (`object-position: center 22%`로 잘린다).
- 테이블 아래쪽 45%는 좌석·카드가 덮이므로 중요한 동작은 화면 위쪽 55% 안에서.
- 클립 첫 프레임과 마지막 프레임이 자연스럽게 이어져야 한다 (루프 재생).
- 인코딩: WebM(VP9) + MP4(H.264, faststart) 둘 다, 3:2 비율(현재 768×512), 24~30fps, 무음, 클립당 2MB 이하. 바이너리에 내장되므로 작게 유지한다.
- 딜링·플립 클립이 기본 자세(오른손은 슈 위, 왼손은 펠트 위, 카메라를 봄)로 끝나면 가장 자연스럽다. 지금 클립은 그렇지 않아서, 웹이 영상 사이를 450ms 동안 겹쳐 바꾼다.

## 캐릭터
- 소피아(sophia): 현재 사진. 검정 치파오, 금색 파이핑, 올린 머리.
- 미아(mia), 하나(hana), 리나(lina): 같은 유니폼, 서로 다른 얼굴·머리 스타일. 각각 초상 1장 + 클립 3개.
